2 · Qué hace el agente

Es un grafo explícito de LangGraph con doce nodos. La regla de diseño: el LLM propone, el código decide.

🧠 El LLM (Qwen2.5-7B)

  • Entiende el mensaje del usuario.
  • Elige una herramienta por paso, en un JSON que una gramática obliga a ser válido: solo puede nombrar productos que existen.
  • Redacta la respuesta, corta y pensada para leerse en voz alta.
  • Como mucho seis pasos por turno.

🛡 El código

  • Valida cada llamada: producto, cantidad, «el segundo» es de verdad el segundo.
  • Existencias y presupuesto se comprueban en la tienda, dentro de una transacción.
  • Comprueba que toda cifra de la respuesta sale de los datos.
  • Repite el pedido y espera un sí inequívoco. Registrar el pedido no es una herramienta del LLM.
  • El pedido se registra una sola vez aunque el «sí» se repita.

4 · Modelos locales y tecnología

Ninguna API externa de inferencia: todo corre en la misma máquina.

Oír

Whisper large-v3-turbo

faster-whisper, español fijo y filtro de voz (Silero VAD)

Decidir

Qwen2.5-7B-Instruct

GGUF Q4_K_M con llama-cpp-python; salida JSON con gramática

Hablar

XTTS-v2

coqui-tts; clona la voz desde una grabación de referencia. Licencia no comercial

Buscar

BM25 + e5-small + reranker

bm25s, FAISS y un reranker entrenado (PyTorch Geometric para GraphSAGE)

Orquestar

LangGraph

grafo explícito, sin agente preconstruido

Vender

SQLite

transacciones para confirmar: todo o nada

Recordar

Postgres

puntos de control de la conversación y preferencias entre conversaciones

Medir

ECAPA-TDNN y jiwer

solo en la evaluación: semejanza de la voz y WER
